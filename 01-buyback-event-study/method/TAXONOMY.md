# events.csv — правила заполнения

Одна строка = одно событие. Кейс протокола обычно даёт 3–6 строк.

## Поля

- `mechanism_type` — конструкция механизма:
  - `buyback_treasury` — выкуп в казну без распределения (текущая программа Lido stETH/LDO)
  - `buyback_burn` — выкуп со сжиганием (MKR исторически)
  - `buyback_distribute` — выкуп с раздачей стейкерам (Aave)
  - `buyback_immutable` — автоматический выкуп, зашитый в протокол (Aavenomics 3.0)
  - `buyback_revenue_gated` — выкуп с гейтом по выручке (Lido NEST)
  - `buyback_treasury_gated` — выкуп с гейтом по остатку казны (схема Кузмича, не реализована)
  - `fee_share` — распределение выручки холдерам без выкупа
  - `ve_lock` — ve-механика, локи за долю выручки/бусты
  - `emission_cut` — сокращение эмиссии/анлоков
- `event_type` — что произошло: `forum_proposal`, `vote_passed`, `first_execution`, `param_change`, `mechanism_upgrade`, `program_end`. Эффект ожиданий мерим от первых двух, эффект потока от `first_execution`.
- `date_precision` — `day` или `month`. События с точностью `month` в event study не идут, пока дата не уточнена.
- `params` — словами: размер, темп, кэпы, гейты, кто исполняет.
- `size_usd_annualized` — годовой темп программы в долларах на момент события. Для расчёта интенсивности (к обороту токена и к выручке протокола).
- `funding_source` — `revenue_surplus`, `all_revenue`, `treasury`.
- `discretion` — `committee` (можно остановить решением), `immutable` (нельзя). Гипотеза о репрайсинге при переходе committee -> immutable проверяется именно этим полем.
- `confounders` — что ещё происходило с токеном в окне ±30 дней: разлоки, листинги, взломы, общерыночные развороты, слухи. Пустое поле означает «не проверяли», а не «ничего не было».
- `verified` — true только если дата подтверждена первоисточником (форум/снапшот/ончейн). Строки с false не идут в выводы.

## Дисциплина заполнения

Источник указывается на дату, а не на пересказ. Для каждого протокола обязательны минимум `forum_proposal` и `first_execution`, потому что разрыв между ними и есть окно эффекта ожиданий. Отрицательные кейсы (программа не помогла или свернулась) ищем целенаправленно, по одному на каждые два-три положительных.
